### 1.2 核心用户旅程

```
新用户：登录(微信授权) → 首次弹隐私协议 → 进入工作台
   ↓
付费：选择积分套餐 → 微信支付 → 回调到云函数 → 入账积分
   ↓
生成：上传原图 → 选预设项目（可多选）→ 可选文字描述 → 提交
   ↓
AI 调用：扣积分 → 云函数调 AI → 写历史/审计 → 返回结果 URL
   ↓
查看/导出：左右滑对比 → 保存到相册/分享 → 30 天后自动过期
```

### 1.3 角色与权限

| 角色 | 入口 | 主要能力 |
|---|---|---|
| **咨询师（终端用户）** | 微信小程序 | 登录、购积分、上传、AI 生成、查看历史、删除、注销 |
| **运营管理员（陈工）** | 运营 H5 后台 | 看订单、看用户、看调用量、处理退款、改模型配置、封号 |
| **系统（云函数）** | 自动 | 自动过期清理、对账、回调、告警 |

## 2. 数据模型（云数据库集合）

### 2.1 业务主表

| 集合 | 关键字段 | 索引 | 说明 |
|---|---|---|---|
| `users` | `_id, openid, nickname, avatar, phone, credits, status, created_at` | openid 唯一, status, created_at | 咨询师账号；`credits` 是冗余余额（缓存） |
| `credit_packages` | `_id, name, credits, price_cents, bonus_credits, validity_days, is_active, sort_order` | is_active+sort_order | 积分套餐（运营可改） |
| `orders` | `_id, order_no, user_id, package_id, credits, amount_cents, status, wx_txn_id, paid_at` | order_no 唯一, user_id+created_at, status | 订单 |
| `generations` | `_id, user_id, original_fileid, result_fileid, preset_keys[], prompt_text, model_used, credits_cost, status, error_msg, expires_at` | user_id+created_at, status, expires_at(TTL) | 生成记录；30 天 TTL 自动过期 |
| `preset_items` | `_id, key, category, name, description, default_prompt, credits_cost, is_active, sort_order` | is_active+sort_order, key 唯一 | 预设项目库（鼻/眼/轮廓/肤质/唇等） |

### 2.2 流水 / 账本

| 集合 | 关键字段 | 用途 |
|---|---|---|
| `credit_ledger` | `_id, user_id, type, amount, balance_after, related_id, note, created_at` | 每次积分变动写一条（recharge/consume/refund/expire/admin），用于对账与回溯 |

> 余额 `users.credits` 是缓存，真账在 `credit_ledger`。对账脚本每日跑一次，发现 `SUM(ledger) != credits` 告警。

### 2.3 配置表

| 集合 | 关键字段 | 用途 |
|---|---|---|
| `system_configs` | `_id(key), value, updated_at, updated_by` | 模型名、限流参数、维护开关、协议版本号 |

### 2.4 审计 / 运维

| 集合 | 关键字段 | 用途 |
|---|---|---|
| `ai_call_logs` | `_id, user_id, generation_id, model, request_size, response_size, cost_cents, latency_ms, success, error_code, created_at` | 每次 AI 调用一条 |
| `download_logs` | `_id, user_id, generation_id, ip, ua, created_at` | 用户下载生成图时记录（合规） |
| `rate_limit_buckets` | `_id(user_id), tokens, updated_at` (TTL 1 分钟) | 令牌桶实现用户级限流 |
| `refunds` | `_id, order_id, user_id, reason, status, amount_cents, operator_id, created_at, completed_at` | 退款申请 |
| `admin_users` | `_id, username, password_hash, role, last_login_at` | 运营后台账号（独立表，不与小程序用户混） |

### 2.5 关键设计原则

1. **图片存云存储，DB 只存 fileID** — 不把 base64 塞 DB
2. **金额一律用整数分** — 避免浮点
3. **敏感字段加密** — `phone` 等用云函数环境变量中的密钥做对称加密后存储
4. **TTL 索引** — `generations.expires_at` 和 `rate_limit_buckets.updated_at` 都用 TTL，数据库自动清理
5. **审计日志只增不改** — APP 层无 update 权限，运营后台只读

### 2.6 横切原则：可运营调整（陈工强调）

> **任何"以后可能变化"的内容，都不允许硬编码在代码里。**

- **预设项目**（20 项及后续增减）：全部在 `preset_items` 集合，运营后台 CRUD；代码里只读不写
- **项目提示词**（default_prompt）：随项目一起存在 DB，调优提示词不发布代码
- **积分扣费规则**（1项=2、2项=3...）：存在 `system_configs.credit_pricing_table`，支持阶梯/封顶
- **积分套餐**（价格/赠送/有效期）：存在 `credit_packages` 集合，运营后台 CRUD
- **AI 模型选择**（主/备模型、限流参数、温度、强度）：存在 `system_configs`
- **限流参数**（每用户每分钟次数、每天上限）：存在 `system_configs`
- **免责协议 / 隐私协议版本号**：存在 `system_configs`，用户首次访问按版本号强制重弹
- **图片保留天数**（默认 30）：存在 `system_configs`，运营可改

代码里**唯一硬编码**的只有"系统级常量"（如：DB 集合名、环境变量名、商户号等真正常年不变的）。

## 设计修订记录

### 修订 1：生成流程改为异步（订阅消息驱动）

**原因**：AI 图片生成通常 10–30s，云函数默认 timeout 20s 容易超时；同步等待用户体验差。

**新流程**：

```
用户提交 → generate.submit 云函数
  ├─ 1. 鉴权 & 参数校验
  ├─ 2. 限流检查
  ├─ 3. 扣积分（事务：credit_ledger + users.credits）
  ├─ 4. 写 generation(status=pending, request_payload)
  └─ 5. 立即返回 { generation_id }           ← 50ms 内返回
                       │
                       ▼ (云数据库 stream 触发器自动)
                  generate.worker 云函数
                       │
  ┌────────────────────┼────────────────────┐
  │ 成功                │ 主模型失败 → 切备   │ 主+备都失败
  │  - 上传结果图        │ - 仍失败则失败分支  │  - 写 failed
  │  - 写 success       │                    │  - 退积分
  │  - 发订阅消息        │                    │  - 发"失败"订阅
  │  - 写 ai_call_logs  │                    │  - 写 ai_call_logs
  └────────────────────┴────────────────────┘
```

**前端配合**：
- 提交后跳"生成中"页，显示 loading + 提示"完成后将通过微信通知"
- 不再需要 `generate.status` 轮询接口
- 用户保持 v1 一次性订阅消息授权（生成前弹一次）
- 收到订阅消息 → 点击进入"结果详情页"

**保留接口**（但仅作补偿）：
- `generate.status` — 用户主动从订阅消息点进来时用，不轮询

### 修订 2：运营后台 v1 单人

- `admin_users.role` 字段**保留**（v1 只用 `super`），未来扩展不改表
- 登录页只有用户名 + 密码
- 不做多账号管理、密码修改、找回 — 陈工您一个人用，初始密码写死在 `system_configs`，首次登录后强制改密码（写到 admin_users.password_hash）
