## 1. 概述

为医美咨询师提供一个**移动端 H5 网页**工具，使其可上传客户照片、选择整形调整部位（预设项目库 + 可选文字描述），由国内大模型生成"整形后"预览图，用于与客户沟通。商业模式为**积分制（按次计费）**，咨询师自助购买积分后即可使用。

### 1.1 关键约束（v2.0 已确认）

| # | 维度 | v1.0 | **v2.0** |
|---|---|---|---|
| 1 | 客户参与 | 咨询师专用 | ✅ 不变 |
| 2 | 收费模式 | 按次计费（积分）| ✅ 不变 |
| 3 | AI 交互 | 预设 + 描述 | ✅ 不变 |
| 4 | AI 模型 | 通义（主）+ 混元（备）| ✅ 不变 |
| 5 | 账号交付 | 全自助 | ✅ 不变 |
| 6 | 隐私数据 | 30 天过期 + 加密 | ✅ 不变 |
| 7 | MVP 范围 | 标准 MVP | ✅ 不变 |
| 8 | **技术栈** | 微信云开发 | **Vue 3 + Vite + Vant / NestJS + PostgreSQL / Docker** |
| 9 | **AI 架构** | 云函数内模块化 | **NestJS 模块 + Bull 队列** |
| 10 | **完成通知** | 微信订阅消息 | **H5 站内通知（轮询/SSE/短轮询）+ 邮件兜底** |
| 11 | 运营后台 | 单人 H5 | ✅ 保留，扩展为 PC 主用 |
| 12 | **合规** | 算法备案 + 协议 | **协议 + AI 角标（无算法备案）** |
| 13 | **登录** | wx.login + openid | **手机号 + 验证码 + JWT** |
| 14 | **支付** | 微信支付 JSAPI | **微信 H5 支付 + 支付宝 H5 支付** |

### 1.2 非目标（v2.0 不做）

- ❌ 微信小程序（不再做）
- ❌ 原生 iOS / Android App
- ❌ 客户侧账号（咨询师专用）
- ❌ 实时音视频咨询
- ❌ 算法备案（仅 H5 网页 + 内部 AI 角标即可，不构成"算法服务"）
- ❌ 多级管理员权限（v2 单人）
- ❌ 完整网安等保认证（v3）

### 3.2 核心用户旅程

```
新用户：手机号 → 收验证码 → 登录（首次弹隐私协议）→ 工作台
   ↓
付费：选积分套餐 → 调起微信/支付宝 H5 → 支付 → 回调 → 入账积分
   ↓
生成：上传原图 → 选预设项目（可多选）→ 可选描述 → 提交
   ↓
AI 异步：扣积分 → submit 50ms 内返回 → 入 Bull 队列
   ↓
Worker：调 AI → 合成角标 → 上传 OSS → 写 success → 站内通知（轮询）
   ↓
查看/导出：通知中心 → 详情页左右滑对比 → 下载 → 30 天后过期
```

### 3.3 角色与权限

| 角色 | 入口 | 主要能力 |
|---|---|---|
| **咨询师** | 用户端 H5（手机/平板）| 登录、购积分、上传、AI 生成、查看历史、删除、注销 |
| **运营管理员** | 后台 H5（PC）| 看订单、用户、AI 日志；改预设、套餐、配置；处理退款；封号 |
| **系统** | NestJS + Cron | 自动过期、对账、回调、告警 |

## 4. 数据模型（PostgreSQL）

所有金额用**整数分**存储。TypeORM 实体 + Migration 维护 schema。

### 4.1 业务主表

| 表 | 关键字段 | 索引 | 说明 |
|---|---|---|---|
| `users` | `id, phone (encrypted), nickname, avatar, credits, status, created_at, deleted_at` | phone 唯一（明文 hash 索引），status，created_at | 咨询师账号；`credits` 是冗余余额（缓存）|
| `credit_packages` | `id, name, credits, price_cents, bonus_credits, validity_days, is_active, sort_order` | (is_active, sort_order) | 积分套餐 |
| `orders` | `id, order_no, user_id, package_id, credits, amount_cents, status, payment_method, txn_id, paid_at, created_at` | order_no 唯一，(user_id, created_at DESC)，status | 订单 |
| `generations` | `id, user_id, original_url, result_url, preset_keys TEXT[], prompt_text, model_used, credits_cost, status, error_msg, expires_at, created_at` | (user_id, created_at DESC)，status，expires_at | 生成记录；定时任务清理 30 天前 |
| `preset_items` | `id, key, category, name, description, default_prompt, credits_cost, is_active, sort_order` | (is_active, sort_order)，key 唯一 | 预设项目库 |

### 4.2 流水账

| 表 | 关键字段 | 用途 |
|---|---|---|
| `credit_ledger` | `id, user_id, type, amount, balance_after, related_id, note, created_at` | 每次积分变动（recharge/consume/refund/expire/admin），可追溯 |

> 余额 `users.credits` 是缓存，真账在 `credit_ledger`。对账 cron 每日跑，发现不一致即告警。

### 4.3 配置表

| 表 | 关键字段 | 用途 |
|---|---|---|
| `system_configs` | `key PRIMARY KEY, value JSONB, updated_at, updated_by` | KV 配置：模型、限流、维护开关、协议版本、提示词前后缀 |

### 4.4 审计 / 运维

| 表 | 关键字段 | 用途 |
|---|---|---|
| `ai_call_logs` | `id, user_id, generation_id, model, request_size, response_size, cost_cents, latency_ms, success, error_code, created_at` | 每次 AI 调用一条 |
| `download_logs` | `id, user_id, generation_id, ip, ua, created_at` | 用户下载生成图时记录（合规）|
| `rate_limit_buckets` | `user_id PRIMARY KEY, tokens, updated_at` | 令牌桶（Redis 实现） |
| `refunds` | `id, order_id, user_id, reason, status, amount_cents, operator_id, created_at, completed_at` | 退款申请 |
| `admin_users` | `id, username UNIQUE, password_hash, role, last_login_at` | 运营后台账号；v2 role=super |
| `user_agreements` | `id, user_id, type, version, accepted_at, UNIQUE(user_id, type, version)` | 协议接受记录 |
| `sms_codes` | `phone, code, expires_at, used, created_at` | 短信验证码（Redis 即可，DB 仅审计）|
| `notifications` | `id, user_id, type, title, body, payload JSONB, read_at, created_at` | 站内通知 |

### 4.5 横切原则：可运营调整

> 任何"以后可能变化"的内容都**不允许硬编码**在代码里，必须存 DB 由后台 CRUD：
>
> 预设项目、提示词、积分扣费规则、套餐、AI 模型选择、限流参数、协议版本、图片保留天数、提示词前后缀 —— 全部 `system_configs` 或专属表。

### 4.6 关键设计原则

1. **图片存 OSS，DB 只存 URL** — 不把二进制塞 DB
2. **金额一律用整数分** — 避免浮点
3. **敏感字段加密** — `users.phone` 用 AES 加密（FIELD_ENCRYPT_KEY 环境变量）
4. **过期清理** — 定时任务（cron）每日清 `generations` 30 天前记录 + 删 OSS 文件
5. **审计日志只增不改** — APP 层无 update 权限，后台只读
6. **软删** — `users.deleted_at`，PIPL 注销 30 天后硬删

## 5. 预设项目库（v2 沿用 v1 的 20 项）

> 业务不变，按 5 大类（鼻/眼/面/颌/肤）各 4 项。详见 v1 design §5（业务内容一字不改）。

积分扣费规则（存 `system_configs.credit_pricing_table`）：
```
1 项  = 2 积分
2 项  = 3 积分
3 项  = 4 积分
4+ 项 = 5 积分（封顶）
```

## 6. AI 调用链与异步流程

### 6.1 异步生成流程（Bull 队列 + Worker）

```
用户提交 → POST /api/generate/submit
  ├─ 1. JWT 鉴权（user guard）
  ├─ 2. DTO 校验（zod）
  ├─ 3. Redis 限流（per_minute, per_day, burst 令牌桶）
  ├─ 4. 查 system_configs.credit_pricing_table → 计算积分
  ├─ 5. 事务（TypeORM EntityManager）：
  │     a) credit_ledger 写一条 consume（amount = -N, balance_after）
  │     b) users.credits 原子 $inc -N
  │     c) 余额 < 0 → 回滚，返回 402 INSUFFICIENT_CREDITS
  ├─ 6. 写 generation(status=pending)
  └─ 7. 入 Bull 队列 ai.generate，立即返回 { generation_id }  ← 50ms 内
                       │
                       ▼
              Bull Worker 进程
  ┌────────────────────┼────────────────────┐
  │ 成功                │ 主模型失败 → 切备   │ 主+备都失败
  │  - 合成 AI 角标水印  │ - 仍失败则失败分支  │  - 写 failed
  │  - 上传 OSS         │                    │  - 退积分（事务）
  │  - 写 success       │                    │  - 写 notification
  │  - 写 notification  │                    │  - 写 ai_call_logs
  │  - 写 ai_call_logs  │                    │
  └────────────────────┴────────────────────┘
```

### 6.2 提示词拼接

```
final_prompt = prefix
             + 拼接( preset.default_prompt, " AND " )
             + ( ", " + translated_user_text if 用户填了描述 )
             + suffix

prefix = "medical aesthetic reference photo, frontal view, high detail, "
suffix = ", preserve ethnicity and facial identity, natural result, no text overlay, realistic photograph"
```

### 6.3 限流（Redis 令牌桶）

`system_configs.rate_limit = { per_minute: 5, per_day: 50, burst: 3 }`
Redis 原子 Lua 脚本：`tokens = MAX(0, tokens - 1); if tokens < 0: 拒`

### 6.4 多模型路由（hot-swap）

`system_configs.ai_models = { primary: {vendor, model, enabled}, secondary: {...}, allow_fallback: true }`
改 DB 一行配置，Redis Pub/Sub 或轮询生效（5 分钟内）。

### 6.5 错误处理与积分回滚

| 场景 | 处理 |
|---|---|
| 余额不足 | 拦截，不扣不退 |
| 限流触发 | 拦截，不扣不退 |
| AI 4xx（参数错）| 标记失败，**退积分**，不重试 |
| AI 5xx / timeout | 重试 1 次，仍败才退积分 |
| 主+备都失败 | 退积分，generation=failed，notification 推送 |
| 用户生成中退出 | 已扣不退（30 天内可看历史）|
| 系统异常（DB 写失败）| 退积分 + 告警通知运营 |

### 6.6 图片安全

- 上传：worker 调 `aliyun-green` 内容安全审核（违规直接拒）
- 调 AI 用 OSS 临时签名 URL，不暴露真实 URL
- AI 返回结果图也走审核，违规标记不展示
