## 1. 概述

为医美咨询师提供一个**微信小程序**工具，使其可上传客户照片、选择整形调整部位（预设项目库 + 可选文字描述），由国内大模型生成"整形后"预览图，用于与客户沟通。商业模式为**积分制（按次计费）**，咨询师自助购买积分后即可使用，凌晨亦可成交。

### 1.1 关键约束（已确认）

| # | 维度 | 选择 |
|---|---|---|
| 1 | 客户参与 | 咨询师专用，不给客户用 |
| 2 | 收费模式 | 按次计费（积分/信用点） |
| 3 | AI 交互 | 预设项目 + 可选描述 |
| 4 | AI 模型 | 国内大模型（主选阿里通义万相，备选腾讯混元）|
| 5 | 账号交付 | 全自助（咨询师付完即用） |
| 6 | 隐私数据 | 严控保留（加密 + 30 天过期 + 手动删 + 审计） |
| 7 | MVP 范围 | 标准 MVP（核心交易 + 合规 + 基础运营后台） |
| 8 | 技术栈 | 微信云开发（云函数 + 云数据库 + 云存储），无域名备案 |
| 9 | AI 架构 | 方案 A 增强版：纯云开发 + 云函数内模块化 `AIService` |
| 10 | 完成通知 | 微信订阅消息（异步推送，非轮询） |
| 11 | 运营后台 | v1 单人使用，保留 role 字段便于扩展 |
| 12 | 合规策略 | 算法备案 + AI 角标 + 免责协议 + 2 年积分有效期 |

### 1.2 非目标（v1 不做）

- 多端（不做 Web 后台独立产品、不做 APP、不做 H5 分享给客户）
- 实时音视频咨询
- 客户侧账号/分享
- 裂变红包、邀请返积分（v1.1）
- 抖音/小红书 KOL 投放（v1.2+）
- 医美机构批量 BD（v1.2+）
- 多级管理员权限（v1 单人）
- 完整网安等保认证（v2）

### 3.2 核心用户旅程

```
新用户：登录(微信授权) → 首次弹隐私协议 → 进入工作台
   ↓
付费：选择积分套餐 → 微信支付 → 回调到云函数 → 入账积分
   ↓
生成：上传原图 → 选预设项目（可多选）→ 可选文字描述 → 提交
   ↓
AI 异步：扣积分 → submit 云函数立即返回（50ms）
   ↓
后台 worker：云数据库 stream 触发 → 调 AI → 写结果 → 发订阅消息
   ↓
查看/导出：用户从订阅消息点进 → 详情页左右滑对比 → 保存相册 → 30 天后自动过期
```

## 4. 数据模型

云数据库 = MongoDB-like 文档库。所有金额用**整数分**存储。

### 4.1 业务主表

| 集合 | 关键字段 | 索引 | 说明 |
|---|---|---|---|
| `users` | `_id, openid, nickname, avatar, phone, credits, status, created_at` | openid 唯一, status, created_at | 咨询师账号；`credits` 是冗余余额（缓存）|
| `credit_packages` | `_id, name, credits, price_cents, bonus_credits, validity_days, is_active, sort_order` | is_active+sort_order | 积分套餐（运营可改）|
| `orders` | `_id, order_no, user_id, package_id, credits, amount_cents, status, wx_txn_id, paid_at` | order_no 唯一, user_id+created_at, status | 订单 |
| `generations` | `_id, user_id, original_fileid, result_fileid, preset_keys[], prompt_text, model_used, credits_cost, status, error_msg, expires_at` | user_id+created_at, status, expires_at(TTL) | 生成记录；30 天 TTL |
| `preset_items` | `_id, key, category, name, description, default_prompt, credits_cost, is_active, sort_order` | is_active+sort_order, key 唯一 | 预设项目库 |

### 4.2 流水账

| 集合 | 关键字段 | 用途 |
|---|---|---|
| `credit_ledger` | `_id, user_id, type, amount, balance_after, related_id, note, created_at` | 每次积分变动写一条（recharge/consume/refund/expire/admin），用于对账与回溯 |

> 余额 `users.credits` 是缓存，真账在 `credit_ledger`。对账脚本每日跑一次，发现不一致即告警。

### 4.3 配置表

| 集合 | 关键字段 | 用途 |
|---|---|---|
| `system_configs` | `_id(key), value, updated_at, updated_by` | 模型配置、限流参数、维护开关、协议版本号、提示词前后缀等 KV |

### 4.4 审计 / 运维

| 集合 | 关键字段 | 用途 |
|---|---|---|
| `ai_call_logs` | `_id, user_id, generation_id, model, request_size, response_size, cost_cents, latency_ms, success, error_code, created_at` | 每次 AI 调用一条 |
| `download_logs` | `_id, user_id, generation_id, ip, ua, created_at` | 用户下载生成图时记录（合规）|
| `rate_limit_buckets` | `_id(user_id), tokens, updated_at` (TTL 1 分钟) | 令牌桶实现用户级限流 |
| `refunds` | `_id, order_id, user_id, reason, status, amount_cents, operator_id, created_at, completed_at` | 退款申请 |
| `admin_users` | `_id, username, password_hash, role, last_login_at, last_change_password_at` | 运营后台账号；v1 role=super |
| `user_agreements` | `_id, user_id, type, version, accepted_at` | 用户协议/隐私协议接受记录 |

### 4.5 关键设计原则

1. **图片存云存储，DB 只存 fileID** — 不把 base64 塞 DB
2. **金额一律用整数分** — 避免浮点
3. **敏感字段加密** — `phone` 用云函数环境变量中的密钥做对称加密
4. **TTL 索引** — `generations.expires_at` 和 `rate_limit_buckets.updated_at` 用 TTL 自动清理
5. **审计日志只增不改** — APP 层无 update 权限，运营后台只读

### 4.6 横切原则：可运营调整

> **任何"以后可能变化"的内容，都不允许硬编码在代码里。**

- **预设项目**（20 项及后续增减）：全部在 `preset_items` 集合，运营后台 CRUD
- **项目提示词**（default_prompt）：随项目一起存 DB，调优提示词不发布代码
- **积分扣费规则**（1项=2、2项=3...）：存 `system_configs.credit_pricing_table`
- **积分套餐**（价格/赠送/有效期）：存 `credit_packages`，运营后台 CRUD
- **AI 模型选择**（主/备模型、限流参数、温度）：存 `system_configs`
- **限流参数**：存 `system_configs`
- **免责协议 / 隐私协议版本号**：存 `system_configs`
- **图片保留天数**（默认 30）：存 `system_configs`
- **AI 提示词前后缀**：存 `system_configs`

代码里**唯一硬编码**的只有"系统级常量"（DB 集合名、环境变量名、商户号等真正常年不变的）。

## 6. AI 调用链与异步流程

### 6.1 异步生成流程（云数据库 stream 触发）

```
用户提交 → generate.submit 云函数
  ├─ 1. 鉴权 & 参数校验
  ├─ 2. 限流检查（rate_limit_buckets 令牌桶原子扣）
  ├─ 3. 查 system_configs.credit_pricing_table → 计算积分
  ├─ 4. 事务：
  │     a) credit_ledger 写一条 consume（amount = -N, balance_after）
  │     b) users.credits 原子 $inc -N
  │     c) 余额 < 0 → 回滚整个事务，返回 402
  ├─ 5. 写 generation(status=pending, request_payload)
  └─ 6. 立即返回 { generation_id }   ← 50ms 内
                       │
                       ▼ (云数据库 stream 触发器自动)
                  generate.worker 云函数
  ┌────────────────────┼────────────────────┐
  │ 成功                │ 主模型失败 → 切备   │ 主+备都失败
  │  - 合成 AI 角标水印  │ - 仍失败则失败分支  │  - 写 failed
  │  - 上传结果图        │                    │  - 退积分
  │  - 写 success       │                    │  - 发"失败"订阅
  │  - 发订阅消息        │                    │  - 写 ai_call_logs
  │  - 写 ai_call_logs  │                    │
  └────────────────────┴────────────────────┘
```

### 6.2 提示词拼接

所有提示词用**英文**（AI 模型对英文支持最好），用户中文描述由后端做一次性翻译。

```
final_prompt = prefix
             + 拼接( preset.default_prompt, 用 " AND " 连接 )
             + ( ", " + translated_user_text if 用户填了描述 )
             + suffix

prefix = "medical aesthetic reference photo, frontal view, high detail, "
suffix = ", preserve ethnicity and facial identity, natural result, no text overlay, realistic photograph"
```

### 6.3 限流（令牌桶）

```
system_configs.rate_limit = {
  per_minute: 5,        // 每用户每分钟 5 次
  per_day: 50,          // 每用户每天 50 次
  burst: 3              // 突发允许 3 个
}
```

实现：`rate_limit_buckets` 集合（TTL 1 分钟），`$inc tokens by -1` 原子操作；< 0 即拒。

### 6.4 多模型路由（hot-swap）

```
system_configs.ai_models = {
  primary:   { vendor: "tongyi", model: "wanx-v1", enabled: true },
  secondary: { vendor: "hunyuan", model: "hunyuan-image", enabled: true },
  allow_fallback: true
}
```

切换模型：改 DB 一行配置，5 分钟内传播生效（云函数有缓存）。

### 6.5 错误处理与积分回滚

| 场景 | 处理 |
|---|---|
| 余额不足 | 拦截，不扣不退 |
| 限流触发 | 拦截，不扣不退 |
| AI 4xx 错（参数错）| 标记失败，**退积分**（不重试）|
| AI 5xx / timeout | 重试 1 次，仍败才退积分 |
| 主+备模型都失败 | 退积分，generation=failed，ai_call_logs 留痕 |
| 用户生成中退出 | 已扣不退（30 天内可看历史）|
| 系统异常（DB 写失败）| 退积分 + 告警通知运营 |

### 6.6 图片安全

- 用户上传：云函数立即 `imgSecCheck` 审核人脸+违规内容
- 调 AI 之前用临时签名 URL，不暴露真实 fileID
- AI 返回的结果图也走审核，违规标记不展示

### 12.3 关键测试用例

- **积分事务**：扣积分时 DB 失败 → 积分不丢 / 用户生成失败 → 自动退
- **AI 降级**：主模型 500 → 切备用成功 / 主+备都失败 → 退积分
- **限流**：连点 10 次 → 第 6 次起 429
- **订阅消息**：worker 成功 → 收到通知 / worker 失败 → 收到失败通知
- **并发**：同一用户同时生成 2 次 → 只扣 2 次积分、不超扣
- **过期**：30 天前的 generation → 自动清理云存储 + DB 标 deleted
